# Barakah Paths — website and Elementor handoff

## Goal
Create a real, browsable Barakah Paths website here, then provide a practical WordPress/Elementor handoff so the same pages can be recreated with editable Elementor sections and widgets. This is a two-stage transfer, not a one-click conversion of the preview's code into Elementor.

## Pages and content
- **Home:** lead with the Barakah Paths name and the family journey from Singapore to Madinah; introduce recent writing, videos, the four main themes, and a path to About.
- **About:** shape the supplied draft into a warm, readable page while preserving its voice and meaning. Keep first-person language; do not invent family details.
- **Journal:** browse stories by family life, homeschooling, Arabic language and culture, and faith. Use clearly identified sample entries until real posts are supplied.
- **Videos:** a dedicated listing with clearly identified sample thumbnails and room for actual video links later.
- Keep navigation, mobile layouts, accessibility, and page-specific search/share metadata in place.

## Visual direction
Use the selected **Warm editorial serif** direction: Fraunces headings, Inter body copy; ink `#2b2620`, warm paper `#f6f1e8`, sand `#e9e0d0`, clay `#b5714a`, sage `#7c8a6b`, and restrained gold `#c9a24b`. Develop a simple Barakah Paths wordmark/monogram with a path motif and generate a small cohesive set of illustrative placeholder photographs (Madinah daily life, family learning, and Arabic study). Label imagery as illustrative, not as the family's own photographs. Keep the editorial composition but remove fictitious statistics, quotes, named family members, published dates, and assumed video content from the chosen visual example.

## WordPress handoff
- Prepare a documented Elementor build map for each page: global colors and fonts, section order, dimensions, image placements, and corresponding native Elementor widgets. Supply the logo and optimized imagery as portable assets.
- Provide importable Elementor template JSON for the static page layouts using standard editable containers/widgets where feasible, with content and image replacement instructions. The live preview's React code itself will not become Elementor-editable merely by uploading it to WordPress.
- Recommend WordPress Posts and categories for the journal and a maintainable video content workflow. Fully Elementor-editable post and archive templates require Elementor Pro's Theme Builder; if the destination uses free Elementor, describe the necessary limitation and alternate theme-managed archive rather than promising full editability.
- Use semantic headings, descriptive URLs, per-page SEO titles/descriptions, alt text, and lightweight responsive images. Avoid heavy animation and unnecessary plugins.

## Transfer boundary and verification
The preview can be built and checked here. Importing, connecting, and validating the Elementor templates on the actual WordPress installation require access to that installation and its Elementor version; that final step cannot be claimed complete from this workspace alone. After the preview and handoff are ready, test the site's links and desktop/mobile presentation, and inspect the handoff assets and JSON structure. Final acceptance on WordPress should include importing each template, replacing sample content, configuring post templates, and checking editability and page speed there.
